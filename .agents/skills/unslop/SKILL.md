# Unslop

Use this standard for every human-facing sentence Leo will read. Apply it to chat, documents, issues, specifications, reviews, commit messages, and prose or comments inside code. Do not announce that you are applying it.

Lead with the point or outcome. Use familiar, concrete words, active voice, and sentences that make the relationship between an action and its purpose clear. Give each paragraph one main job. Use lists only when they make parallel items or steps easier to compare.

Cut filler, repeated claims, generic transitions, inflated phrasing, unnecessary hedges, and signposting that merely announces the next sentence. State each point directly and let it stand on its evidence. Keep technical detail when it helps the reader understand evidence, a decision, or a limitation.

Preserve the writer's meaning, evidence, uncertainty, citations, notation, and established voice. Make no claim stronger than its support. When editing existing prose, do not change a substantive choice while improving its wording. Keep executable syntax unchanged; comments and other natural-language text inside code follow this standard.

**Done:** the main point appears early, each sentence says something useful, the wording is direct, and the text still means what the author intended.
