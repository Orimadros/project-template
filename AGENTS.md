# Research project template

1. Leo owns every substantive choice about the research, data, models, and presentation. Identify choices that arise, explain the options and tradeoffs, give a recommendation, and wait for his decision. Agents may choose coding details that leave the meaning unchanged. Teach methods when Leo invokes `teach` or `grill-to-spec`; for a complex method he may not know, briefly offer an explanation before implementation. Routine calculations need no such prompt.
2. Preserve an instruction beyond the current task only when Leo deliberately asks to write and route it through a project document or skill. Do not turn corrections into memory or new skills on your own.
3. Use GitHub issues for work Leo asks to track. One issue has at most one immutable spec describing its change, written through `to-spec` or `grill-to-spec`. `implement` places spec work under `pending-approval/`; `code-review` checks it; `ship` incorporates only the subset Leo names; `close-issue` commits, pushes, and closes it. An exact small edit can go straight to the working copy; exploration stays under `code/99_explorations/`. Neither needs an issue or spec unless Leo requests tracking.
4. Keep a script's current purpose, inputs, outputs, and substantive choices in the script. Use agreed canonical datasets and register direct local inputs through `code/lib/project_io.*` for runs that produce data or results. Existing files under `data/raw/` are append-only. Data and results come from code, and the paper at `docs/deliverables/articles/main/main.tex` is authoritative for research claims; slides derive from it.
5. Apply `.agents/skills/unslop/SKILL.md` to every natural-language string Leo will read. Run the relevant checks before reporting completion. After substantial work, write a factual log in `docs/work/session_logs/` for `sitrep`. The skills in `.agents/skills/` hold task procedures and coding preferences; `CONTEXT.md` defines template terms, and `README.md` maps the repository. Supply skill content to agents deliberately when a task calls for it.
